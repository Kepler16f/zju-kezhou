# 教师模式（导师审阅）合规与实现说明

> 目标：让**本科生导师/新生之友/学业辅导员**能审阅学生的学业达成情况，
> 同时**不引入任何教务写接口、不新增任何教师端爬虫通道、不改变 App 的只读承诺**。
> 核心思路：**数据主权在学生** —— 学生用既有登录拉取本人数据，自愿导出一份
> 脱敏「学业档案分享包」发给导师；导师端是**不登录教务的纯审阅态**，只解析分享包
> 并复用既有审计引擎出报告。
>
> 代码位置：`lib/data/share_pack.dart`（包格式与脱敏）、
> `lib/pages/teacher_review_page.dart`（审阅页）、
> `lib/pages/settings_page.dart`（学生导出入口 + 切审阅态入口）、
> `lib/main.dart`（教师态视图分支、导出实现、审阅引擎注入）。

## 1. 为什么不做「教师端直连」（被否决的路径 A）

正方教师端确有成绩查询（cjdr）、教师课表、班级名单等端点，技术可行，但：

- **合规**：学生成绩/学籍是《个人信息保护法》下的敏感个人信息，处理需学生**单独同意**。
  内置"用教师账号批量拉取他人成绩单"会把个保法风险与校规风险（教务系统禁止爬虫）
  公开化，并**绕开**当前"仅处理用户本人数据"的整条合规链路（AI 脱敏、check_readonly.py、
  只读对外承诺）。
- **工程**：教师端是另一套 gnmkdm/页面/JSON 形态，≈重做半个 zju_client；WAF 软封禁面翻倍。
- **价值错位**：真需要批量教务管理的教师有官方系统，其诉求全是写操作，恰是本仓红线所禁。

> 若将来取得**院系/学校层面书面授权**（校级项目身份），路径 A 可单独评估，
> 届时应做进**独立内部版**，不进公开版。

## 2. 只读红线如何被遵守

- `lib/` 与 `engine/` 全程**不引用任何教务写接口路径**（`xkBcZyZzxkYzb` 等），
  `eval/check_readonly.py` 在 CI 机械拦截——本功能没有触碰任何名单内标记。
- 导师审阅模式**不发起任何教务网络请求**：分享包本身就是全部数据源。审阅页在
  `main.dart` 的 `_teacherMode` 分支里渲染，该分支不建立教务会话、不出现四页签与 AI 悬浮入口。
- 学生侧数据主权：导出动作由学生在设置页显式触发，传输走聊天工具发文件，
  **App 不含服务端**，不经任何中间服务器。

## 3. 分享包格式（`kez.share-pack` v1）

字段级白名单脱敏是事实源（`shareRowKeepFields`）。导出行**只保留**：

| 保留 | 含义 |
|---|---|
| `course_id` / `name` | 课程身份与名称（方案匹配用） |
| `credits` | 学分 |
| `passed` | 是否通过（布尔，审计计分的关键） |
| `semester` | 学期编码 `YYYY-A/B/C` |
| `category` | 课程类别（学分看板用） |
| `credit_included` / `gpa_included` | 是否计入修读/GPA |

导出行**绝不带出**（白名单事实源 + `scanSensitiveKeys` 兜底扫描，测试强制）：

- `grade`（数字分数）、`five_point` / `five_point_source`（绩点）；
- `original`（教务原始成绩文本，数值型如 "90" 即分数本体——2026-10-21 评审发现后移出白名单）；
- `xkkh`（选课凭证号）、任何凭证/会话字段；
- 学号（`student` 段无 `student_id` 字段）。

顶层结构：`{format, version, exported_at, student{alias,major,grade,current_semester},
plan, courses[], privacy_notice}`。`plan` 为本次审计所用方案快照（可空，空则依赖审阅者本机专业方案）；
`student.alias` **默认「匿名同学」**，实名需学生显式勾选，实名文本来自本机教务档案姓名。

导入侧（教师端）双重校验：结构校验 + 敏感键复扫（防御纵深，即便学生手改文件也不消费敏感键）。
版本高于本机支持值 → 拒入并提示升级。

## 4. 引擎复用与"审阅意见"口径

- 分享包 → `sharePackToRecord()` 产出与教务链路同形的 `record`，直接喂既有
  `AuditEngine.main()`；内嵌方案通过 `registerRuntimePlan` 注册，**引擎零改动**。
- UI 复用方案页同款可嵌入 `ReportSection`（当初拆成 `List<Widget>` 正方便独立渲染）。
- **脱敏的预期副作用**（非缺陷）：包内无分数 → 引擎的"未通过课程需重修"（failed_recheck）
  提醒天然不生成，审阅意见只呈现板块缺口与结构性风险（毕业风险等）。这与"不传成绩明细"
  的合规目标一致。

## 5. 与 AI 链路的一致性

审阅页可选接入 AI 助手：发送内容走 `ai_prompts.auditSubsetOf` 白名单子集，与选课页/方案页
同一脱敏口径——姓名/学号/成绩明细/教务凭证/方案原文一律不出境；同意流程与页脚由 `ai_chat`
层统一负责。教师态不配置 AI 时该入口隐藏。

## 6. 待验证 / 后续

- LIVE 视觉验收：装机后走一遍"学生导出 → 教师导入"全链路（含真机剪贴板）。
- P3（未做）：多份分享包批量导入 → 班级维度统计（完成度分布/共性缺口）。因每份数据
  均学生自愿分享，隐私上仍成立，但当前版本先交付单份审阅。
- 若分享包要跨版本兼容，格式变更须升 `sharePackVersion` 并保留旧版本导入分支。
