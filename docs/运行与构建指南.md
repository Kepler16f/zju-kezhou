# 运行与构建指南

> 面向"怎么把它跑起来"：本地跑、真机跑、打包、以及本机（受限沙箱）里怎么验证。

## 0. 前提

- Flutter：任一满足 `sdk: ">=3.3.0 <4.0.0"` 的版本。两种已验证组合：
  - 官方 stable（Windows 桌面/Android/iOS/Linux/macOS）；
  - `flutter-ohos` **3.27.5-ohos-1.0.8**（鸿蒙 HAP，Dart 3.6）。
- **平台脚手架**：`compass.zip` 里已带 `windows/ android/ ios/ linux/ macos/`；若你手上只有
  `lib/ test/ assets/ pubspec.yaml`，用 `flutter create --platforms <平台> .` 现场生成即可
  （CI 就是这么做的，见 `.github/workflows/`）。Windows 侧的产物名由
  `windows/CMakeLists.txt` 的 `set(BINARY_NAME "kezhou")` 决定 → `kezhou.exe`。
- 首次 `pub get` 需要网络。国内环境建议：
  ```bash
  set PUB_HOSTED_URL=https://pub.flutter-io.cn
  set FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn
  ```

## 1. 本地桌面跑（最快看到效果）

```bash
cd compass_app
flutter create --platforms windows .   # 仅首次：生成 windows/ 脚手架，不会覆盖 lib/
flutter pub get
flutter run -d windows
```

`flutter run` 起来后进底部导航的 **「方案」** 页，用浙大通行证登录即可拉取培养方案。

> **中文用户名注意**：`path_provider_android 2.3+` 依赖 `package:jni`，其 CMake 在含中文的
> `PUB_CACHE` 路径下 ninja 会报路径语法错。仓库已锁 `path_provider_android: 2.2.12` 规避；
> 想用新版就把 `PUB_CACHE` 指到纯 ASCII 路径（如 `D:\pubcache`）。

## 2. 单测

```bash
cd compass_app
dart test                       # 全量（纯 Dart 用例）
dart test test/engine_test.dart  # 单个文件
```

> 本机若为定制 Flutter 分支，`flutter test` 会因 SDK hash 卡住，用 `dart test` 代替。
> `test/widget_test.dart`、`test/live_probe_test.dart` 需要真实设备/网络，属可选。

**鸿蒙 HAP**（`.github/workflows/build-hap.yml` 的本地等价流程）：

```bash
# 1) 用 flutter-ohos 分支的 flutter
git clone --branch 3.27.5-ohos-1.0.8 --depth 1 https://gitcode.com/openharmony-tpc/flutter_flutter.git ~/flutter_ohos
export PATH="$HOME/flutter_ohos/bin:$PATH"
# 2) 注入 path_provider 的 openharmony-sig fork（仅 ohos 构建需要）
cat >> compass_app/pubspec.yaml <<'EOF'
dependency_overrides:
  path_provider:
    git:
      url: https://gitee.com/openharmony-sig/flutter_packages.git
      path: packages/path_provider/path_provider
EOF
cd compass_app
flutter create --platforms ohos .          # 生成 ohos/ 脚手架
flutter pub get
flutter build hap --release --target-platform ohos-arm64   # 需 DevEco Studio / 鸿蒙 SDK；未配签名产出 *unsigned*.hap
```

## 3.1 Windows 一键构建 + 本地安装（x64）

`packaging/build_and_install_windows_x64.ps1` 把「构建 → 组装（含 VC++ 运行库）→ 生成安装包 → 装到本机」串成一条命令：

```powershell
# 先体检（不构建、不安装）：一眼看清缺什么
pwsh -File packaging\build_and_install_windows_x64.ps1 -DryRun

# 正式：构建 + 生成 Setup.exe + 静默安装到本机
pwsh -File packaging\build_and_install_windows_x64.ps1

# 装完直接启动 / 只构建不安装
pwsh -File packaging\build_and_install_windows_x64.ps1 -Launch
pwsh -File packaging\build_and_install_windows_x64.ps1 -SkipInstall
```

前置（脚本会逐项体检并打印对应安装命令）：Flutter SDK、VS 2022 Build Tools 的「使用 C++ 的桌面开发」
（组件 `Microsoft.VisualStudio.Component.VC.Tools.x86.x64`）、可选 Inno Setup 6。

安装方式自动二选一：

| 条件 | 方式 | 安装位置 | 卸载 |
|---|---|---|---|
| 找到 `ISCC.exe` 且未加 `-Portable` | Inno Setup 标准安装包 | `%LOCALAPPDATA%\Programs\KeZhou`（`PrivilegesRequired=lowest`，免管理员） | 设置 → 应用，或 `unins000.exe` |
| 未找到 Inno / 指定 `-Portable` | 用户级便携安装 | `%LOCALAPPDATA%\Programs\KeZhou` | `%LOCALAPPDATA%\Programs\KeZhou\uninstall.ps1` |

> **可执行文件名**：`windows/CMakeLists.txt` 里 `set(BINARY_NAME "kezhou")`，所以 `flutter build windows`
> 产出的是 `kezhou.exe`（与历史脚本、CI 里写的一致）。新脚本仍不硬编码 exe 名——优先 `kezhou.exe`，
> 否则取 Release 目录里体积最大的 `.exe`；快捷方式与 `.iss` 的
> `UninstallDisplayIcon`/`[Icons]`/`[Run]` 都用探测到的真实名字，将来改名或重新生成 `windows/` 脚手架也不会失效。
>
> **AppId**：本地 `dist/kezhou_x64.iss` 与 `build_windows_installer.sh` 用 `...KEZHOU00001`，CI 用 `...KEZHOU00002`。
> 新脚本默认 `...00001`，与本地既有安装一致 → 直接覆盖升级，不会并排装出两份。

> **本机沙箱限制（重要）**：本会话的沙箱禁止 Dart 进程创建子进程，且这台机器上没有
> Flutter / Visual Studio / CMake / Ninja，所以**无法在本会话内真正构建或安装**；此处只能做到
> 体检级验证（语法解析、路径/版本/工具链探测、检测函数单测 19 项）。构建与安装请在你自己的
> Windows 机器上执行上面的命令。

**脚本编码约定**：`packaging\*.ps1` 一律 **UTF-8 with BOM**——PowerShell 5.1 按 GBK 读无 BOM 的中文脚本会乱码。
## 3.2 应用图标（全平台一套源图）

图标只有一个源：`compass_app/assets/brand/icon_source.png`（1024×1024 圆角方形）。
`packaging/make_icons.py` 从它派生并**直接写回各平台目录**（产物已入库，平时无需重跑）：

```bash
python packaging/make_icons.py            # 全平台
python packaging/make_icons.py --only android,windows   # 只出某几个平台
```

| 平台 | 产物 | 裁切策略 |
|---|---|---|
| Android | `mipmap-*/ic_launcher{,_round}.png` + `mipmap-anydpi-v26/ic_launcher{,_round}.xml`（自适应图标） | 前景=字标（62% 安全区），背景=满幅渐变；系统圆形/圆角矩形裁切都不切主体 |
| iOS | `ios/.../AppIcon.appiconset/*.png` | 满幅**不透明**方形（iOS 自行裁圆角，不允许透明） |
| macOS | `macos/.../AppIcon.appiconset/*.png` | HIG 风格圆角方，内容占 82.4%，四周留白透明 |
| Windows | `windows/runner/resources/app_icon.ico` | 圆角矩形 + 透明角（16–256 多尺寸） |
| 鸿蒙 | `assets/brand/ohos/*`（CI `build-hap.yml` 注入脚手架） | 分层图标 `layered_image.json`：前景 + 背景，同 Android 语义 |

脚本内部处理：源图四角在圆角外是白色 → 调和填充补满（用弧内真实像素扩散，
无接缝）；右下角淡白 "AI" 水印 → 整块调和填充抹除；字标提取按"白色程度"
抠图并裁到外接框。

## 4. 真机跑需要什么

- 登录浙大通行证：手机连校园网，或已开通校外访问（WebVPN 可能有额外跳转，App 只走统一认证入口）。
- 拉培养方案走的是只读教务接口，凭证只存在设备沙箱（`path_provider` 目录），不上传。

## 5. 本机（受限沙箱）里的验证方式

本机的执行沙箱**禁止 Dart 进程创建子进程**，于是：`flutter` 工具链整体不可用（它要 spawn `where aapt`、
`dart pub get`）、`dart test` / `dart analyze` 也不可用（要 spawn 子进程或 analysis server）。
所以本机用两个替代脚本取得**真验证**（不是 lint 级）：

```powershell
# 1) 真编译级类型检查：dart pub get + 引擎 frontend_server 编译每个 dart 文件
powershell -ExecutionPolicy Bypass -File work\build_check.ps1

# 2) 真跑单测：单进程直跑仓库全部纯 Dart 用例（用完自动还原 package_config.json）
python work\run_tests.py
```

原理见 `work/PROGRESS.md` 第 6 节。**在正常机器上不需要这些，直接用 `flutter`/`dart test` 即可。**

## 6. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 改窗口大小闪退（Windows） | 引擎无障碍桥空指针，见 `已知问题-Windows窗口resize崩溃.md` |
| `flutter test` 卡住不出结果 | 定制 Flutter 分支的 SDK hash 问题 → 用 `dart test` |
| `flutter pub get` 报 ninja/CMake 路径错 | `PUB_CACHE` 含中文 → 换纯 ASCII 路径，或保留 `path_provider_android: 2.2.12` 锁 |
| 登录一直失败 | 看 App 右上角 🐞 登录诊断日志，对照 `实测登录指南.md` |
| 方案页提示 910/无权限 | 明细/PDF 端点对部分账号返回 910，页面上以结构化视图兜底，属预期行为 |
