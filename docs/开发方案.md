## 0. 验收定义（Definition of Done）

**P0 链路（必须有，10/15 晚跑通）**：
```
用户在 WebApp 选专业 + 粘贴成绩单（或上传导出表）
  → 30 秒内返回 Markdown 格式的三色达成度报告
  → 报告含：每模块已修/应修/缺口、三色标记、先修风险提示、开课学期风险提示、
     每条结论的课程名+培养方案页码溯源、免责声明
  → 同一入口追问政策问题 → RAG 回答带【文档名·页码】；问超范围问题 → 标准拒答并指向部门
```

**P0 的四个"演示不翻车"保障**：①计算全在 Code 节点；②3 组已验证输入固化（见 §7.3）；③golden JSON 冻结进代码（见 §3.2）；④本地 Python 同逻辑备份可跑通（见 §10）。

**P1（加分，按 10/14 go/no-go 决定是否启用 M6 与 API 适配器）**：教务导出 CSV 真实数据、班级缺口看板、100 字段评测表、30+ 人试用与计时数据。

                 └─────────────────────────┼────┼───────┼────┘
                                           ▼    ▼       ▼
 计算层  Code节点规则引擎：课程匹配 → 模块汇总 → 缺口 → 三色 →

## 4. M1 培养方案结构化 —— Workflow「罗盘·方案结构化」

**定位：一次性离线工具 + 答辩演示件。** 每个专业跑一次，产物经人工订正后冻结为 golden。

### 4.1 Workflow 节点链

```
开始(文件输入: 培养方案PDF; 文本输入: 专业名)
→ 文档提取器（获取全文）
→ Code：按"模块标题行"切块（正则切分课程表区间，块大小≤LLM上下文，保页码标记）
→ 迭代节点：对每个课程表块 → LLM抽取（JSON模式） → Code校验
→ Code：合并去重（course_id/name 双键）、模块学分求和
→ Code：全局校验（§4.3）→ 输出 {plan.json, check_report.md}
```

### 4.2 抽取提示词（LLM 节点，`prompts/m1_extract.md`）

```
你是教务数据抽取器。从下面的培养方案课程表片段中抽取每门课程，只输出 JSON 数组，不输出任何解释。
每门课的字段：
- name: 课程全称（照抄原文）
- credits: 数字（学分）
- nature: 只允许 通识必修|必修|限选|任选|实践（按表格所在栏目判定）
- offered: 数组，只允许 "秋"/"春"；原文未标注则输出 ["秋","春"] 并在 note 字段写 "原文未标注开课学期"
- prereq_text: 先修要求原文（无则空字符串）
- page: 该课程在原文中的页码（依据文本中 [PAGE:n] 标记）
规则：1) 不推测、不补全、不合并课程；2) 表格行不完整（缺学分）也要输出并把缺失字段置 null，由校验层处理；3) 只输出 JSON。
[PAGE:23] ...课程表原文...
```

要点：页码标记 `[PAGE:n]` 由切块 Code 注入（Dify 文档提取器分段带页码信息，若 aihub 版本不带，则由文档解析时人工加页码锚——C 的活儿）。`prereq_text` 保留原文，id 解析放在合并阶段做（跨块引用无法在单块内解析）。

### 4.3 校验规则（Code 节点，自动 + 人工清单）

| 检查 | 动作 |
|---|---|
| 必填字段非空、credits∈(0,20] 且为 0.5 步长 | 违规行进 `rejects.md`，人工回原文改 |
| 每模块 `sum(credits) == 方案声明的模块学分` | 不等则整模块标红，人工核 |
| `prereq_text` 解析：先修课名 → course_id（difflib 匹配 ≥0.85） | 匹配失败进 `unresolved.md` 人工定 |
| 总学分 vs 方案"毕业总学分"声明 | 偏差>2 阻断 |
| page 越界 | 置 null 并记录 |

**验收标准（对应进度表）**：10/13 晚 1 份 PDF 结构正确率 ≥80%（按抽检字段算，脚本见 §8）；10/14 两专业 golden 冻结。

### 4.4 泛化对照的演示口径

答辩现场对**第二个专业跑一次 M1 到"抽取+校验"输出**，展示的是流程泛化，不承诺现场出完美结果（校验报告会显示需人工订正的条目——这是诚实，也是 M5 里"人机协同兜底"的论据）。

## 6. M3-lite 先修 + 时间冲突 —— 只检不改

M3 没有独立应用，就是 §5.3 的 `time_conflict` 探测器 + `offering_missed` 的学期比较逻辑（`sem_key`）。时间冲突纯算法（`engine/timecheck.py`，≤60 行，B 在 10/15 上午交付）：

```python
def check_time_conflict(slots_a, slots_b):
    """slots: [{day:1-7, start,end 节次, week_start, week_end}]
    同 day 且节次区间相交 且 周次区间相交 → 冲突。返回冲突课程对。"""
    for sa in slots_a:
        for sb in slots_b:
            if (sa["day"] == sb["day"]
                and sa["start"] <= sb["end"] and sb["start"] <= sa["end"]
                and max(sa["week_start"], sb["week_start"]) <= min(sa["week_end"], sb["week_end"])):
                return True
    return False
```

数据来源：开课学期课表 JSON（学生计划选课表由试用同学提供或 C 合成；培养方案只有课程列表没有上课时间，时间冲突演示用样例课表——**这条边界写进申报书，不装作有全校课表数据**）。

## 7. M4 政策 RAG 问答 + 拒答

### 7.1 知识库配置（3 份文件：学籍管理、交换项目、推免政策）

- 分段：高质量模式，**父子分段**（父块=带页码的原文节，子块=语义段）——保证引用页码可回指；
- 检索：混合检索，Rerank 开；召回阈值 0.5（10/16 按评测集调）；Top-k 4；
- 引用：知识检索节点开启"引用与归属"，答案强制附 `【文件名·P页码】`。

### 7.2 拒答分支（Code + 条件节点，不经 LLM）

```
知识检索 → Code①: 对检索结果做 {命中数, 最高得分, 是否含请求主题词} 打分
→ 条件分支: 得分<0.5 或 命中=0 → 直接回复固定文案：
   "该问题超出我掌握的3份政策文件（学籍/交换/推免）范围。为避免误导，不作回答。
    请查阅：本科生院官网 / 你的学院教务科（附联系方式）。"
→ 否则 → LLM（系统提示词 §7.3）
```

固定文案由 C 与 D 在 10/15 前确定口径；**答辩演示"正确拒答"用的问题固化**：`"我们学校大三转专业绩点排名怎么算体育算不算？"`（真实、超范围、可当场演示拒答+指路）。

## B. 真实教务数据接口（合规设计，App 轨核心）

协议事实（来自 Helechron 调研，端点为公开协议行为，不受版权保护）：
1. **ZJUAM 统一认证**：`zjuam.zju.edu.cn/cas/login` 取 execution → `/cas/v2/getPubKey` 取 RSA 公钥 → 密码裸 modPow（BigInt，padLeft 128 hex）→ POST 表单 → 取 `iPlanetDirectoryPro` Cookie。
2. **正方教务 zdbk**：CAS service 双跳（`login_ssologin.html`）换 `JSESSIONID+route` 成对 Cookie → POST `cxdy/xscjcx_cxXscjIndex.html?doType=query` 取成绩单 items（字段 `kch/kcmc/xf/cj/xnxq/kcxzmc`）。
3. 防护经验：校内域强制直连代理、host 级并发限流、指数退避、会话过期单飞重登。

**实现**（`compass_app/lib/data/zju_client.dart`，独立重写，未复制 GPL 源码）：
- 只读：仅成绩查询，无任何写操作；字段最小化（裁剪为 Record Schema 六字段）。
- 凭证：App 沙箱混淆文件（`credential_store.dart`，P1 可换系统 Keystore 后端，接口已留）。
- Cookie 仅内存；成绩缓存沙箱可一键清除；限流 3 并发 + 抖动 + 网络抖动 3 次退避。
- 演示场景仍走样例模式；真机用学生本人账号，属"本人主动查本人数据"。
- **传输层实战要点**（首版校园网登录失败的根因，本版已全部对齐 Helechron 验证过的行为）：portal 自签名证书容忍（`badCertificateCallback`）、`*.zju.edu.cn` 强制 DIRECT 直连绕过代理/TUN、用 `dart:io HttpClient` 拿原生 Cookie 对象、正方接口参数在 URL 而提交体为空、学期从选课课号 `xkkh` 切片（"20232024-1"段）、SSO 票据 2 分钟 TTL 过期自动重登、会话过期自动重建重试一次。

## B. "不用轮次"的实现（答辩口径）

- zdbk 各轮次是**页面内嵌入口**（onclick，无独立轮次接口）——App 自动解析"当前页面可用的选课入口"，
  不做"正在进行"的强断言；
- 同一教学班跨轮次身份 = 课程ID + 教学班ID（三档降级链：完整键 → 教师+时间指纹 → 仅课程聚合），
  **轮次只作观测维度**：容量/已选随轮次的变化可对比展示，匹配从不依赖轮次编号；
- 与培养方案/审计联动：缺口课程、先修完整性、开课季匹配、与当前课表的时间冲突全部走确定性计算
  （时间冲突复用 `Timeline.slotsConflict`，新增课表 kbList→时隙解析，单双周逐周展开）；
- 数据面只读：提交/退课/批次接口只在文档登记，`eval/check_readonly.py` 在 CI 机械拦截（负向注入实验通过）。

## C. AI 解读的边界设计（"可信"论述素材）

  学号、姓名、成绩明细、凭证、方案原文一律不出设备；审计告警按**类型白名单**转发
  （`failed_recheck` 会携带不及格分数——发布前对抗评审实测捕捉并修复，有回归测试）；
