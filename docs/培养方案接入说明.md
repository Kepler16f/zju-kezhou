# 培养方案接入说明（zdbk 取数与匹配）

> 目标：用**浙大通行证登录 + 专业名称**全自动匹配到本人培养方案并爬取接口，在 App 内直接观看。
> 代码位置：`lib/data/zju_client.dart`（取数）、`lib/data/plan_models.dart`（匹配模型）、
> `lib/pages/curriculum_plan_page.dart`（观看页，底部导航「方案」）。
> 接口行为均为**真机实测**（2026-10 于 zdbk.zju.edu.cn 验证）。

## 1. 数据流

```
浙大通行证登录（CAS，见实测登录指南）
        │  JSESSIONID + route
        ▼
fetchStudentProfile()   ← 课表接口 kbcx/xskbcx_cxXsKb（专业/学院/行政班/学号/姓名，扁平字段）
        │  zy=专业名, xy=学院, xzb=行政班(→年级)
        ▼
fetchPlanCatalog()      ← 方案列表接口（一次拿全校 ~3000 条，缓存到本地）
        │
        ▼
matchPlans(catalog, majorName, grade)   ← 客户端评分匹配（服务端不支持按专业名过滤）
        │
        ├─ 唯一强匹配 → 直接选定
        └─ 有歧义（多条相近）→ **候选列表交给用户点选**（不替用户猜）
        ▼
fetchPlanCourseTable()（best-effort 逐门课程）+ planFileFromSummary（兜底）
        ▼
「方案」页结构化观看：概览 / 学分学制 / 培养目标与要求 / 专业核心课·核心实践课·前沿与荣誉课程
                        / 课程表 / 辅修说明 / 二三四课堂 / 官方 PDF（可选下载）
```

同时，登录后自动把选中的方案注册成审计用的运行时方案（`resolveAuditPlan`），
「审计」页的达成度报告即基于教务实时方案。

## 2. 接口清单

| 用途 | 方法与路径 | 关键参数 | 备注 |
|---|---|---|---|
| 登录 | `GET/POST /cas/...` | RSA 加密密码 | 见 `实测登录指南.md` |
| 学生信息 | `POST /jwglxt/kbcx/xskbcx_cxXsKb.html?gnmkdm=N2151&su=<学号>` | `xnm=2026-2027&xqm=3` | 返回**扁平** `zy/xy/xzb/xh/xm`；这是唯一在本实例可用的专业来源 |
| **方案列表** | `POST /jwglxt/pyfagl/pyfaxxcx_cxPyfaxscxIndex.html?doType=query&gnmkdm=N153020&su=<学号>` | **body 必须只有** `queryModel.showCount=5000&queryModel.currentPage=1&_search=false` | 一次返回全校约 3000 条，`totalPage=1` |
| 课程明细 | `POST /jwglxt/pyfagl/pyfaxxcx_cxPyfaxsKcList.html` | `jxjhh` / `pyfaxx_id` | 学生账号多回 **HTTP 910**（usable=false）→ best-effort |
| 方案查看/打印 | `fwglxt/pyfagl/pyfaxxcx_cxPyfaxsView.html`、`..._dyPyfaxs.html` | `pyfaxx_id` / `jxjhh` | 同上，多回 910 |
| **方案 PDF** | `GET /jwglxt/pyfagl/pyfayl_cxPyfaylPdf.html?id=<jxjhh>&doType=query` | `id` = **教学计划号 jxjhh**（不是 pyfaxx_id） | 二进制 PDF，带 magic-byte 校验 |

### 踩过的坑（都已修，且写了回归用例）

1. **列表接口不接受 `zymc`/`njdm_id`**：多带任何一个不认的参数 → 服务端返回 HTML 错误页 →
   `json.decode` 抛异常。只认 `synj`(年级)/`zydm`(专业代码)/`xydm`(学院)/`jxjhh`。
   > 因此"按专业名称匹配"**必须在客户端做**（拿全量再筛），不是服务端查询。
2. **方案主键是 `pyfaxx_id`/`jxjhh`**，不是 `pyfa_id`/`id`——旧代码因此永远挑不到方案。
3. **年级来自行政班末四位的前两位**：`工科试验班（计算机）2606` → 2026。
   旧代码取"后两位"→ 2006，年级一错方案全错。
4. 学生账号访问明细/打印页端点会拿到 **910**（教师菜单），所以逐门课程表只能 best-effort，
   页面上以方案汇总行（61 个字段）为主体，并如实标注数据质量。

## 3. 匹配算法（`matchPlans`）

名称层级（`PlanSummary.levelFor`，均为归一化后比较：全角括号→半角、去空白、忽略大小写）：

| 层级 | 判定 | UI 文案 |
|---|---|---|
| `exact` | 方案名 == 专业名 | 专业全称 |
| `prefix` | 互为前缀（含方向班变体，如 `信息安全（数字安全方向）`） | 名称前缀 |
| `contains` | 互相包含 | 名称包含 |
| `category` | 只在 `zydlmc/zydlmc2`（大类名）里命中 | 大类名称命中 |
| `none` | 不相关，丢弃 | — |

打分：`层级权重 + 年级分 + 主修加成`，其中

- 年级：与本人年级一致 **+60**；往届按差距递减；**未来年级 -20**（防止高年级方案被选中）；
- 主修加成 **+6**（`dlbsmc` 含"专业"才算主修，辅修/双学位方案不占优）；
- 同 `id` 去重，保留最高分。

**歧义判定**（`PlanMatchResult.ambiguous`）：前两名分差 < 20，或同年级存在多条同级命中
（学院/方向/培养类型不同）→ 判为歧义，页面提示"请在候选列表里点选确认本人方案"，
并把候选列出来让用户点选；**不会替用户盲选**。

其它提示（`notes`）：本人年级无方案时降级到往届并提示；候选多于一条时提示确认；
非主修方案（辅修等）单独提示。

### 大类方案的取舍（容易搞错的一点）

方案名与查询名**逐字相同**时判 `exact`，即使这个名字本身是个大类名（如"工科试验班（计算机）"）。
若把它降级成 `category`，大类方案会输给"只在它的大类名里命中 + 主修加成"的某个专业方案，
**反而把按大类招生的学生错配到具体专业方案上**。反向的保证由另一条用例守住：
某个专业方案只是"在大类名里出现"时，必须报 `category`，绝不能冒充专业全称命中。

## 4. 结构化观看的内容

方案列表接口这一行有 61 个可用字段（`work/plan_fields.txt` 是实测样本），页面用到：

- 概览：专业名/专业代码/学院/专业大类/年级/学习形式/授予学位/校区/培养类型/审核状态
- 学分：最低毕业学分、分项学分（辅修/二专/二学位/二三四课堂…）、要求学分
- 培养目标与要求：`pymb` / `pyyq`
- 课程名列表（空格分隔，已归一化为 chips）：`zyhxkc`（专业核心课）、`zyhxsjkc`（核心实践课）、`qywkc`（前沿与荣誉课程）
  - 与本人成绩单里同名课程比对，**已修的高亮**
- 课程表（best-effort）：课程名/代码/学分/学期/性质/教师
- 辅修说明 `bz`、第二三四课堂 `dektbz`/`dektxf`、官方 PDF

**数据质量如实标注**：拿不到逐门学分时不假装完备（`meta.quality` + `verified=false`），
页面上以提示条展示。

## 5. 缓存与凭证

- 方案目录（约 3000 行）缓存在设备沙箱，避免每次进页面都拉全量；
- PDF 以二进制缓存（`credential_store.saveBinaryCache`，文件名 `cache_*` 前缀，随清缓存一起清）；
- 用户手动点选的方案 id 也持久化（`savedPlanId`/`clearPlanSelection`），下次进页面直接用它。
